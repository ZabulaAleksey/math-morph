# Context Policy

## Цель

Сохранять высокую точность Codex без постоянного засорения context window длинными правилами.

## Правила

1. Корневой `AGENTS.md` — только стабильные инварианты и маршрутизация.
2. Доменная детализация находится в локальных `AGENTS.md` рядом с кодом.
3. Повторяемые процедуры оформляются Skills: Codex видит метаданные и загружает полный `SKILL.md` только при выборе workflow.
4. Если опциональный project SessionStart hook будет явно включён, он возвращает только краткий указатель на активный контекст и короткий фрагмент `docs/PROGRESS.md`.
5. Subagents узкие; их результаты должны быть краткими и доказательными.
6. MCP сервера и toolsets включаются только по необходимости.
7. Не вставлять весь `PROMPTS.md`/`ROADMAP.md` в каждую сессию.
8. Использовать поиск по именам этапов/секций и читать целевые фрагменты.
9. Не дублировать одинаковые правила в нескольких AGENTS; локальный файл должен содержать только отличия/дополнения.
10. Hook output должен быть кратким; большие отчёты сохранять в файл и ссылаться на него.

## Маршрутизация задачи

Для проектных инструкций применяй наиболее конкретный релевантный слой:

1. текущая задача пользователя;
2. ближайший локальный `AGENTS.md` целевого модуля;
3. корневой `AGENTS.md` и `docs/AI_DEV_TEAM_COMPATIBILITY.md`;
4. только относящиеся к задаче SPEC, architecture/ADR, stage prompt и тесты;
5. унаследованные общие правила AI Dev Team.

Более конкретный слой уточняет общий, но не отключает системные ограничения и правила безопасности. Если документы противоречат друг другу, остановись на минимальном непротиворечивом контексте и исправь канонический источник вместо добавления ещё одного дубликата.

Для реализации этапа используй `docs/TRACEABILITY.md` как индекс, а не как второй источник требований. Канонические требования остаются в `docs/SPECIFICATION.md`, порядок реализации — в `docs/ROADMAP.md`, исполняемый срез этапа — в соответствующей секции `docs/PROMPTS.md`.

## Контроль дрейфа

- При изменении границ модулей, направлений зависимостей, публичных интерфейсов или deployment assumptions сравни diff с `docs/ARCHITECTURE.md`. Намеренное изменение фиксируется в ADR; случайное считается дефектом.
- При UI-изменениях сравни реализацию с `docs/DESIGN.md`, существующими компонентами и визуальными паттернами. Пока `DESIGN.md` пуст, применяй правила `apps/web/AGENTS.md` и не создавай новый visual language без запроса владельца.
- Экспериментальную технологию добавляй только после фиксации цели, альтернатив, feature flag/isolation, fallback, тестов и измеримого критерия успеха.

## Рекомендуемый budget

- Root AGENTS: ~3–6 KB полезного текста.
- Local AGENTS: обычно <2 KB каждый.
- SessionStart additional context: <=2 KB.
- Subagent отчёт: findings first, без пересказа всей кодовой базы.
- Skills: длиннее допустимо, потому что используются через progressive disclosure.

## Что не загружать автоматически

- весь backlog;
- весь roadmap;
- старые архитектурные обсуждения;
- неактуальные отчёты;
- все fixtures;
- все MCP instructions;
- все Skill bodies.
